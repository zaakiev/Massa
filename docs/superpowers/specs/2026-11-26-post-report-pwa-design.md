# Дизайн: разбор суточного отчёта таможенного поста (PWA)

Дата: 2026-11-26  
Статус: на ревью  
Платформа: Progressive Web App под iPhone (домашний экран)

## Цель

Приложение принимает фото бумажного суточного отчёта таможенного поста «Морской торговый порт Махачкала», распознаёт бланк и показывает:

1. Краткую сводку смены  
2. Структурированные таблицы по разделам  
3. Контроль рисков  
4. Архив отчётов и статистику за период  

Общая база поста: все авторизованные по коду поста видят все загруженные отчёты.

## Вне объёма (v1)

- Нативное приложение в App Store / SwiftUI  
- Личные аккаунты пользователей  
- Полный офлайн-OCR без интернета  
- Роли и права доступа (начальник / инспектор)

## Доступ и идентификация

- Вход: один общий **код поста**  
- При загрузке отчёта: выбор **номера смены** и **фамилии из справочника**  
- Справочник смен и фамилий правится в настройках (доступны после входа по коду поста)

## Входные данные

- Фото бланков (камера iPhone), обычно 2 страницы:
  1. Ежедневный отчёт по таможенным операциям (рейд, убытие, простой, размещение на причалах)
  2. Временное хранение / ПЗТК (ВХ, ПДТ с борта, операции на причалах, иные товары)
- Один «отчёт смены» = дата + смена + фамилия + 1…N фото

## Разделы данных

| Раздел | Содержимое |
| --- | --- |
| Суда на рейде (прибытие) | судно, страна/дата, товар, тонны |
| Суда в ожидании убытия | судно, страна, товар, тонны |
| Прибытие / убытие (верхняя таблица) | причал, флаг, агент, отправитель, получатель |
| Причины простоя | причина, начало, окончание |
| Простой с начала года | часы, дни (нарастающим) |
| Размещение на причалах | судно, причал, борт, дата стоянки, этапы, статус, товар |
| Временное хранение (ВХ) | судно, причал, ДО-1, сроки ВХ, товар, тонны/места, статус, наряд, вывезено, остаток |
| Итог ВХ | всего партий; разбивка по видам товаров; **Выпущено ДТ** |
| Оформление с борта (ПДТ) | судно, причал, даты, товар, количество, наряд, остаток; нарастающий итог ПДТ |
| Операции на причалах | вид операции, судно, причал, время, товар, количество, статус |
| Операции смены | ДО1, ДО2, Таможенное наблюдение (ТН), ДТ ИМПОРТ, ДТ ЭКСПОРТ |
| Иные товары на ПЗТК | лесоматериалы (м³, т, ДТ), калий хлористый (биг-бэги, ДТ) и аналогичные позиции |
| НШС (ТП) | нештатная ситуация уровня таможенного поста (факт / описание) |

## Подписи в интерфейсе (канон)

Писать именно так:

- Выпущено ДТ  
- Иные товары на ПЗТК  
- ПДТ  
- ДО1  
- ДО2  
- Таможенное наблюдение (ТН)  
- ДТ ИМПОРТ  
- ДТ ЭКСПОРТ  
- НШС (ТП) — расшифровка: нештатная ситуация уровня таможенного поста  
- кубические метры — сокращённо **м³**  
- тонны — **т** где уместно в таблицах  

Списки товаров на ВХ и операций смены — **каждая позиция с новой строки**, не в одну строку через «·» или «;».

Без подчёркиваний в подписях UI (`Вып_ДТ` недопустимо → `Выпущено ДТ`).

## Экраны

1. **Вход** — код поста  
2. **Лента** — отчёты по датам (дата, смена, фамилия, статус рисков)  
3. **Новый отчёт** — смена + фамилия → фото → распознавание → правка → сохранение  
4. **Карточка отчёта**
   - Сводка: рейд / убытие / простой; блок ВХ (партии построчно + Выпущено ДТ); операции смены построчно; НШС (ТП); ПДТ нарастающим  
   - Таблицы: разделы бланка + Иные товары на ПЗТК  
   - Риски: сроки ВХ, простой, незакрытые операции, НШС (ТП)  
5. **Статистика** — период (неделя / месяц / свой): простои, суда, тоннаж, число отчётов по сменам  
6. **Настройки** — фамилии, смены, смена кода поста  

Макет (черновик UI): `mockups/iphone-report-app.html` и PNG в `mockups/`.

## Риски (автоматически)

- Истекающий / просроченный срок ВХ  
- Простой за сутки и нарастающий простой  
- Незакрытые операции (статус «начата» и т.п.)  
- НШС (ТП), если отмечена в отчёте  
- Пустые ключевые блоки при наличии данных на фото (после OCR — предупреждение на экране правки)

## Архитектура

```
iPhone (PWA)
  → вход по коду поста
  → загрузка фото
  → API бэкенда
       → хранение фото
       → OCR / разбор бланка
       → сохранение структурированного отчёта
  → UI: лента / карточка / статистика
```

- **Клиент:** веб-приложение (PWA), адаптив под iPhone  
- **Бэкенд:** API + хранилище файлов + БД  
- **OCR:** облачный разбор таблиц/текста бланка на сервере; результат проходит через экран ручной правки перед сохранением  
- **Сеть:** новая загрузка и OCR требуют интернет; уже сохранённые отчёты можно просматривать офлайн (кэш PWA) в разумных пределах v1  

## Модель данных (логическая)

- `Post` — код доступа (хеш), настройки  
- `ShiftLabel` / `OfficerName` — справочники  
- `Report` — дата, смена, фамилия, статус OCR, флаги рисков, timestamps  
- `ReportPhoto` — файлы страниц  
- `ReportPayload` — JSON по разделам (рейд, убытие, простой, ВХ, ПДТ, операции, иные товары, НШС)  
- Агрегаты для статистики считаются из сохранённых `Report` / `ReportPayload`

## Ошибки и правка OCR

- Если распознавание частично не удалось — показать, какие блоки пустые/сомнительные  
- Пользователь может править поля до сохранения  
- До нажатия «Сохранить» можно заменить фото и перезапустить распознавание; после сохранения правка полей — через редактирование карточки (без обязательного повторного OCR)

## Тестирование (критерии приёмки)

1. По двум эталонным фото (как в примерах от 25.11.2026) после правки сохраняется отчёт с разделами ВХ, операции, Иные товары на ПЗТК  
2. Сводка показывает партии ВХ построчно и **Выпущено ДТ**  
3. Операции смены построчно: ДО1, ДО2, Таможенное наблюдение (ТН), ДТ ИМПОРТ, ДТ ЭКСПОРТ, ПДТ  
4. Подписи UI соответствуют канону выше  
5. Два пользователя с одним кодом поста видят одну ленту  
6. Статистика за период считает простои / суда / отчёты по сменам  

## Рекомендация по реализации

PWA + облачный бэкенд — основной путь. Нативный iOS — вне v1 (нужны Mac, Apple Developer, App Store).
